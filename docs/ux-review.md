# UI/UX の見直し（7a-1）

スマホで、片手で、すきま時間に、迷わず使えることを目的に、画面を見直した記録です。方針は `docs/design.md`。

## 1. 見直す前の画面で使いにくかった点

2026-11-15 に、iPhone 15（WebKit）、Pixel 7（Chromium、ライト・ダーク）、幅360px（Chromium）で、ゲストとして主な画面を撮影して確認した。

### ホーム
- 最上段は「続きから」だけ。**今日なにをやればよいか**、**どこが弱いか**が、ひと目で分からない
- 解き始めるには「問題を解く」→ 出題条件の画面 →「この条件で始める」と進む。前回と同じ条件で解くだけでも、毎回、長い出題条件の画面を通る
- 分野別の成績が8行とも並び、解いていない分野は「— (0)」が続く。情報は多いが、次の行動につながらない
- 一番下の出典の文章が、下のナビゲーションに一部隠れる

### 下のナビゲーション
- アイコンが文字（⌂ ✎ ▤ ⚙）で、端末やフォントによって形・太さがそろわない
- 「出題」という名前が、学生にとって「解く」より分かりにくい。次に足す閲覧モードの入口がない

### 出題条件
- 14回のチップ、8分野、出題数、順番、絞り込みが縦に長く並び、幅360pxでは「この条件で始める」まで何度もスクロールする
- 下に固定した「この条件で始める」とナビゲーションが重なり、画面の下のほう（出題数の選択など）が隠れて見える
- 何問になるかが、始めるまで分からない

### 解答画面
- 選択肢の番号「(1)」の列が広く、本文が狭い。選択肢の高さは足りているが、番号と本文の区切りが弱い
- 解答前は、画面の下半分が空いたまま。片手で届く下のほうに操作がない
- 解答後の正誤（○ 正解／× 不正解）が選択肢の下にあり、選択肢が長いと画面の外に出て見えない
- 「次へ」ボタンが解説の文章に重なる。**前の問題に戻る方法がない**（スワイプは「次へ」だけ）
- 右上の☆が「あとで見直す」の意味だと分かりにくい
- 「←」が、中断なのか前の問題なのか分かりにくい

### 図の問題
- 図はタップで全画面になるが、拡大はブラウザ自身のピンチズームに任せていて、全画面の中では拡大しにくい（ページ全体が拡大される）

### 記録
- 分野別・日別とも表だけで、どこが弱いかを目で追う必要がある。回別の成績がない

### 全体
- 初めて使う人向けの説明がない
- 読み込み中は灰色の帯だけで、何を待っているのか分からない。記録がないときの文言が短い
- ダークモード・文字サイズの変更は使えるが、文字を「特大」にすると、ナビゲーションの文字が詰まる

撮影した画像は、作業したPCの一時フォルダに置いた（リポジトリには入れない）。

## 2. 見直した点

方針は `docs/design.md`。データの形・Firestore ルール・セキュリティの設定は変えていない。

| 画面 | 見直す前 | 見直した後 |
|---|---|---|
| ホーム | 最上段は「続きから」だけ。成績の表が長い | 最上段に「続きから」「今日やること」「弱点」。どれも1タップで1問目が出る（解き始めるまで1タップ） |
| 下のナビゲーション | ホーム・出題・記録・設定。アイコンは文字 | ホーム・解く・読む・記録・設定。線の太さをそろえた SVG アイコンと文字。選択中は上に印 |
| 解く（出題条件） | 長い条件の画面を毎回通る | 最上段に「前回の条件で始める」。回は「最新の回だけ／すべての回」で一度に選べる。下に、選んだ条件の要約 |
| 解答画面 | 正誤は選択肢の下。前に戻れない。「←」が中断か分かりにくい | 下に固定した段に、正誤（記号＋文字＋色）と「前へ」「次へ」。左右スワイプで前後に移る。中断は「×」、★は「見直す」の文字つき。選択肢は高さ60px、番号を丸で示す |
| 図の問題 | ブラウザのピンチズーム頼み | 拡大表示の中で、2本指の拡大・ダブルタップ・ボタン（＋・−・元に戻す） |
| 記録 | 表だけ | 分野別・回別の正答率を横棒（合格の目安60%の線つき）、直近14日の解答数を縦棒。数値は文字でも出す |
| 読む | なし | 閲覧モードの入口（7a-2 で実装するまで準備中の案内） |
| 初めて使う人 | 説明なし | 初回だけ1画面の説明（スキップできる） |
| 空・読み込み中 | 灰色の帯、「まだ記録がありません。」 | 何を待っているか（「記録を集計しています…」）、記録がないときは次にすることとボタン |

## 3. 独立レビュー（2026-11-15、別のエージェント・opus）

見直した後の画面（iPhone 15・Pixel 7 のライト／ダーク・幅360px）を、スクリーンショットで見てもらった。指摘は高1・中8・低12件。

### 直した点

| 重さ | 指摘 | 直したこと |
|---|---|---|
| 高 | 問題の見出しの右の「×」（過去の正誤）が、中断の「×」や閉じるボタンと紛らわしい | 「これまで ○×」の文字つきのバッジにした |
| 中 | 正誤を下に固定したので、解説が画面の外に隠れて気づきにくい | 正誤の横に「解説」ボタン（押すと解説までスクロール）を置いた |
| 中 | 選ばなかった選択肢の文字が薄く、ダークで読みにくい | 文字は本文の色のままにし、番号の丸だけ薄くした |
| 中 | 図の拡大で、後ろの画面が透け、「閉じる」が折り返す | 背景を不透明にし、閉じるボタンの文字を折り返さないようにした。案内の文を短くした |
| 中 | 幅360pxで、選択中の回のチップが2行になる | チップの文字を折り返さず、列の幅を広げた |
| 中 | 記録で、分野名が「…」で切れる | 分野名は2行まで折り返す |
| 中 | 日別のグラフの日付が割れ、棒が1本だけでグラフに見えない | 直近14日の軸を必ず描き（解いていない日は空の枠）、日付は週の区切りと今日だけ出す |
| 中 | 下の「回・分野を選んで解く」が破線で、無効に見える | 実線の枠にした |
| 低 | 回別の14行のうち、ほとんどが「未解答」で長い | 解いた回だけを棒にし、残りは「まだ解いていない回（N回）」に折りたたんだ |
| 低 | 見出しが1文字だけ次の行に落ちる | 見出しを言葉の区切りで折り返す（`word-break: auto-phrase`。対応しているブラウザだけ） |
| 低 | 初回の説明で、ボタンに青いフォーカスの枠が最初から付く | 最初のフォーカスを見出しに置き、フォーカスの枠を主な色にそろえた |
| 低 | ダークの初回の説明で、シートと背景の差が小さい | 背景を暗くし、シートの上の端に線を引いた |
| 低 | 押せない「次へ」が押せそうに見える | 押せないボタンは、灰色の面と灰色の文字にした |
| 低 | 折りたたみ（選択肢ごとの説明・根拠の資料）に開け閉めの印がない | 右に開け閉めの印を付けた |
| 低 | 報告ボタンが押せないのに、ボタンの形で出ている | 準備中の1行の案内にした |
| 低 | 「文字サイズ」などの見出しが枠線に重なる形と、カードの中の形が混ざる | すべてカードの中に置く形にした |
| 低 | 「端末に合わせる」が2行に折れる | 「自動」にし、下に説明を1行足した |
| 低 | 文字のリンク（最新の回だけ など）の押せる範囲が狭い | 高さ48pxの小さな枠のボタンにした |

### 直していない点

- 図の問題の選択肢が「(1) (1)の図」と番号が2回並ぶ：問題データ（選択肢の文字）の形なので、データの形を変えない今回は直していない
- 出題条件の画面で、下に固定した部分（要約・始めるボタン・ナビゲーション）が高い：要約は条件を確かめるのに使うので残した

## 4. 速さ

Pixel 7 相当（CPU 4倍遅く、回線は速い3G 相当）で、ゲストのホームを5回開いた中央値。ばらつきが大きい（同じ版でも FCP が 1.9〜2.5 秒）ので、見直す前と後を続けて2回ずつ測った。

| | 見直す前 | 見直した後 |
|---|---|---|
| 最初に読み込む JS・CSS（gzip） | 89.9 KB | 93.2 KB |
| 最初の表示（FCP） | 1.89〜2.49 秒 | 1.78〜1.87 秒 |
| 読み込み完了 | 1.02〜1.13 秒 | 1.14〜1.18 秒 |
| ホーム → 出題条件 | 0.43〜0.71 秒 | 0.35〜0.38 秒 |
| 出題条件 → 1問目 | 0.54〜1.18 秒 | 0.62〜0.65 秒 |
| オフライン（回線を切って読み込み直す） | ホームの表示・出題とも可 | ホームの表示・出題とも可 |

最初の画面に要らない画面（記録・読む・管理・初回の説明・図の拡大）は、使うときに読み込む形に分けた（Service Worker が前もって保存するので、オフラインでも開ける）。

# 7a-2（閲覧モード・検索・要復習マーク・メモ）

## 5. 独立レビュー（2026-11-15、別のエージェント・opus）

iPhone 15・Pixel 7（ライト／ダーク）・幅360px のスクリーンショット23枚を見てもらった。指摘は高1・中6・低9件。

### 直した点

| 重さ | 指摘 | 直したこと |
|---|---|---|
| 高 | 絞り込みの「解説の確信度」の4つのボタンが幅に収まらず、「低（確認中）」が1文字ずつ縦に並ぶ | ほかの段と同じ丸いチップにして「すべて・高・中・低」と短くし、「低」の意味は下に1行で書いた |
| 中 | 要復習を付けたときの金色が、明るい背景で薄い（コントラスト 3:1 未満） | ライトは濃い金色（`#8a5a00`）にした。ダークは今の明るい金色のまま |
| 中 | 「要復習」と「要復習★」の違いが小さく、今の状態か押すものか分かりにくい | 付いているときは「要復習中」とし、薄い面を敷いた。メモも「メモあり」で同じ形にそろえた |
| 中 | 一覧の要復習・メモの印がアイコンだけで、文字がない | 「★要復習」「メモ」と文字を添えた |
| 中 | 幅360pxで、一覧の右端の印が切れて見えなくなる | 印を回・問のすぐ後に置き、幅が足りないときは分野名のほうを「…」で省く |
| 中 | 絞り込みの面が長く、選んだあとに件数を見るには上まで戻る必要がある | 面の最後に「N問を見る」（件数入り・押すと閉じる）と「すべて外す」を置いた |
| 中 | 書きかけのメモが、背景のタップや×で確かめずに消える | 書きかけのときは「捨てますか？」と確かめる |
| 低 | 1問の画面の前後のボタンがアイコンだけ／上の戻るボタンと紛らわしい | 「前」「次」の文字を添え、上の戻るボタンは「一覧」と文字入りにした |
| 低 | 検索欄の×、メモの「編集」の高さが48pxに足りない | 48pxにした |
| 低 | 2語で検索したとき、抜き出しに片方の語しか出ないことが多い | 違う語をいちばん多く含む部分を選び、両方の語が入るなら両方が見えるように切り出す |
| 低 | 検索欄の例が切れる | 「キーワードで検索」だけにした |
| 低 | 「回」だけ「すべて」のチップがない | 「回」の先頭にも「すべて」を置いた |
| 低 | ダークで、選ばれている切り替えボタンが明るいピンクのまま | 主なボタンと同じ暗めのベリーにそろえた |
| 低 | はじめの案内が「あとで見直す」のまま | 「★で要復習に。メモも書ける」にそろえた。`docs/design.md` も直した |

### 直していない点

- 要復習・メモのボタンが右上にあり、左手では届きにくい：よく押すものではないので、使われ方を見てから考える

## 6. 速さ（7a-2）
